# TileForge Studio development

Read DEVELOPMENT-HANDOFF.md before changes. This is a companion editor in its own repository, not the Legends game.

- Primary platform: Android tablets, landscape first; preserve touch targets, stylus/pointer input, and usable smaller-screen behavior.
- Preserve owner Porymap edits. Import/export source paths exactly. Compare original SHA-256 before integration. Never blindly overwrite current game files or modify the game repository automatically.
- Map block fields: metatile bits 0–9, collision bits 10–11, elevation bits 12–15. Editing any field must preserve the others. Collision fills must preserve visual tile IDs.
- Preserve indexed PNG pixel indices, palette order, and bit depth. Resolve actual source symbols and custom asset paths; do not assume conventional tileset directories. FRLG layouts have a different primary tile/metatile/palette split.
- Keep the APK, web app, help and README consistent. Never claim universal map detection, automated decompilation, ROM rebuild, or Android runtime verification without evidence.
- Keep the APK keystore private and reuse it for future updates. Never commit it to this public repository. It is excluded from Git.
- Run focused binary/round-trip and conflict checks after parser/export changes. Use the connected GitHub tools for repository writes. Publish the generated docs/ mirror for Pages, and verify the live app and APK before reporting them complete.
- Update the handoff at each milestone with verification and outstanding limitations. No game ROMs or proprietary tool code may be committed.

- Preserve the Load → Studio → Export entry flow: never open an editing map before the user chooses a project or draft. Keep the practice island an explicit choice.
- Check compact layouts in both orientations and at handheld-PC scaling. Keep the map canvas within the usable viewport, tool panels reachable, thumbnails larger than source pixels, and Undo labelled.
- Drafts must retain original baselines, independent project identities, and binary undo/redo entries. Cancel a pending autosave before replacing its workspace. Border editing must write only the declared border file and preserve unrelated block bits.

- The owner explicitly approved enabling GitHub Actions for this repository on 2026-10-22. Pages uses the prepared Actions workflow; routine future publications do not need that same permission requested again. Keep landing-page aesthetic changes scoped to the landing page unless the user also asks to restyle the editor.

- New Legends/source imports prefer Littleroot when present; saved project/draft selections take priority. The optional offline practice island lives in Help. Never skip the project Load stage.
- Category inference must use descriptive labels, behaviors or conservative map-event evidence. Strip tileset namespaces before classifying; keep uncertain tiles in Other. Preserve legacy pair-scoped category keys while writing new tags/pins by format, source symbol and local metatile ID. Show actual primary/secondary provenance and location usage without implying a borrowed set was copied from one unique map.
- Keep the release query on editor module/CSS URLs, relative module imports, and service-worker precache URLs consistent when releasing, so existing browser caches cannot silently retain old code. Android asset URLs use their path; query versions must remain compatible with bundled assets.

- Reviewed artwork categories must require the exact inspected primary/secondary PNG and metatile hashes and fill only Other. Keep uncertain/blank entries unclassified; primary inherited labels must not leak to unrelated pairs. Guide changes should preserve the distinction between local drafts, portable projects, changed-source exports and the separate game build.

- Keep Paint, Fill, Pick and Move text visible at all viewport widths. New source/ROM workspaces open in Move; new source projects prefer explicitly labelled plain grass, then short-grass behavior, with a valid first-tile fallback. Preserve the active tool across ordinary map changes and the saved brush when restoring drafts.

- Location switches reset palette browsing filters/scroll to the layout's current saved tileset pair, without reverting edited pair references. Event review is advisory: disclose unloaded/external dependencies and never promise arbitrary script correctness. Only deterministic, previewed, stale-guarded corrections may write source fields, with Undo. Local-model output is plain text with no executable/source-write path. AI assets load on explicit request and cache separately from editor updates.
- Draft Delete moves a snapshot to Deleted drafts, preserving baselines/history for Restore. Serialize deletion/restoration behind pending writes; detach the open draft and cancel its pending autosave before deleting it. Keep the header Guide entry visible on every viewport and preserve the workspace beneath guide dialogs.

- Existing event markers and Select event open a read-only summary first; Edit event is explicit. Move-mode taps may inspect a marker or complete explicitly chosen event placement, but drags/cancelled captures must keep panning without opening a summary. Preserve overlapping-event selection and read-only inspection of specialized events; never infer a script's full purpose from its label.

- Area stamps capture complete original block words; write only the explicitly selected art/movement mask. Preserve destination movement by default, require the source pair/format for art, clip edges without row wrapping and keep each placement one Undo entry. Stamps belong in draft/portable-project metadata, never changed game files. Ruler, selection and map PNG export are read-only.
- ROM search/navigation/bookmarks must never write ROM bytes. Raw 08/09 pointer candidates are not semantic anchors or proof of references. Retain explicit ASCII-versus-game-text limits, in-range checks, result caps and chunk-boundary coverage. Bookmark metadata lives in ROM drafts, not ROM exports.
- Compact tool popovers must fit the actual remaining viewport height after their header, with internal scrolling. Keep the existing editor structure and visible core tool labels.

- Source metatile composition patches only the selected 16-byte entry; preserve attribute files and unrelated block fields. Palette edits change one declared JASC-PAL RGB row, retaining other rows/newlines and PNG indices/bit depth. Both editors stage previews, show exact shared source paths, reject stale dependencies and record one Undo only on Apply. Preserve unsupported mappings rather than guessing.

- Updates: keep Settings and Guide reachable without hiding Save draft or core tool labels. Native updates use only the official Pages manifest/APK paths and explicit user actions; validate bounded metadata, size/SHA-256, package, versionCode and installed signer before Android confirmation. Keep the read-only URI provider unexported with temporary grants. Web refresh must save a draft first, confirm the new entry is published, and preserve IndexedDB/local-model caches. Update metadata must bypass the service worker cache. Never bundle update.json in the APK; generate it from the final signed bytes, increment versionCode, and publish it with the APK.

- Two-finger navigation must cancel uncommitted paint/fill/area gestures and suppress the remaining finger until release. Original comparison renders a separate baseline snapshot, never swaps or writes workspace bytes, and preserves Undo/zoom/scroll. Palette resizing remembers orientation-specific UI widths only and refits solely in Fit mode.

- Fold/compact palettes use a drawer up to 1100 CSS pixels; keep the JS and CSS breakpoint aligned. The inspector must be the sole vertical palette scroll surface. Keep Browse & filter tiles collapsible and passage-only brushes elevation-preserving; combined elevation presets are explicit. Beginner ? help stays open until dismissed, including nested palette/event dialogs. Android configuration changes must retain the WebView/workspace for fold/unfold and DeX.

- Keep Windows desktop bundled assets identical to dist alongside APK/docs. New cells must append stable map IDs, clear inherited events/scripts/connections, and preview atomic Undo transactions. Preserve createdPaths absent baselines across portable-project import. Warp indices are zero-based internally; show entrance coordinates in the guided UI and retain existing indices. Map creation requires both map_groups.json and the exact global data/event_scripts.s index; do not broaden integration writes beyond explicit supported paths.

- Map properties may change only explicitly supported existing fields, with newly selected constants validated against project definitions. Mirrored connections must update both maps atomically and refuse conflicting/mismatched edges; rectangle geometry previews are not rendered terrain. Replace artwork must preserve all movement bits. Terrain shift must wrap full block words and explicitly keep events/scripts/connections fixed with acknowledgement; never imply coordinated resizing or event relocation.

- Draft capacity is 10 active source/ROM snapshots per app/browser profile, enforced atomically for new writes and restoration. Updates to active drafts must work at capacity; never auto-delete or trim legacy data. Preserve DRAFT_LIMIT errors and visible full-slot recovery routes. Goal chooser/guidance must not apply game edits automatically. NPC pictures must follow explicit source declarations, use static-frame/default-palette disclosure, lazy-load visible entries, isolate workspace changes, retain actual custom paths and show placeholders instead of guessed/dynamic sprites. Referenced sprite assets are read-only and must not broaden integration writes or be committed as bundled game artwork.

- NPC browsing defaults to the project-wide source graphics catalog, independent of terrain tilesets and current map placements. Keep placed events in the explicit On this map tab with read-only summaries. Catalog selection only arms placement; preserve the chosen graphics ID through the save form, and retain placeholders for missing pictures. Never treat range/count sentinels, macro names or runtime-variable slots as fixed NPC appearances.

- Permanent draft deletion is explicit and confirmed from Deleted drafts only. Queue it behind pending writes; recheck deleted state transactionally, refuse active entries for single deletion, and skip restored entries during bulk removal. Bulk confirmation captures exact keys so later deletions are not silently purged. Never auto-empty Deleted drafts or clear active drafts, open workspace bytes, source files, exports, or other caches.

- Android safe areas belong to the native SafeAreaLayout parent: size the real WebView inside system-bar/display-cutout/mandatory-gesture/keyboard bounds, never use WebView padding as the safe-area fix. Forward zeroed handled inset types on every update to avoid duplicate/ghost padding, and retain workspace state during configuration changes. Browser/PWA dialogs, pickers, grips, floating panels and toasts must fit usableViewport(), including side cutouts and visual keyboard bounds. Native system areas must never be guessed from a device model or hardcoded CSS pixels.

- Initialize the Android window decor before accessing its inset controller. Apply system-bar appearance after attachment as well. Native window/layout changes must run the separate Android instrumentation checks; CSS-only browser geometry is insufficient evidence for system-bar behavior.

- Floating tool menus need a visible, touch-sized top-right close button in a sticky header. Close and Escape ask Close this menu? with Keep menu open focused first; cancelling preserves the open panel. Confirming NPCs & events closes event mode, while Done retains its existing tuck behavior. Return focus to the tool summary after dismissal and preserve workspace edits.

- Map studio is the primary visible workspace. Keep Pixel studio, ROM workspace and Resume draft inside the hamburger workspace menu at every width. Source/ROM transitions must retain existing replacement checks; cancelling the ROM picker must preserve the source map. All routes home from an open workspace ask Return to home? with Keep editing first; returning home preserves the workspace and Back to studio restores it.
- Border preview starts enabled, without changing border bytes. Compact/tablet editors must scroll past tool rows to a useful canvas rather than shrinking it; preserve map pan/paint gesture behavior within the canvas.
- NPC preview resolution includes obj_frame_tiles, U16/U32 declarations, matching-byte-area frame geometry, berry/field-effect tables and explicit default player aliases verified against source state counts. Never invent a runtime appearance or an unassigned image: show visible explanatory Live/None labels only when source declarations prove those cases. Keep read-only preview metadata/assets in source packs; no game artwork is bundled with TileForge.

- Approved Classic UI direction: Tiles / Collision / Events in the main map navigation; one right-hand inspector (drawer up to 1100px). Keep advanced/raw movement and occasional map tools tucked away. All-project tile browsing starts checked and never paints foreign pair IDs directly. Browse compatible referenced source pairs, virtualize thumbnails, show load errors/retry, and preview explicit pair changes with stale guards and Undo. Preserve real draft-save access and source bit fields.
- User approved proceeding without routine previews on 25 October 2026. Show design previews only when explicitly asked; internal visual QA remains required.
